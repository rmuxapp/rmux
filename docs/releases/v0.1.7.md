# rmux 0.1.7 — preview

This release improves everyday keyboard navigation, project switching, and
workspace controls.

## VS Code and macOS

- Use rmux as VS Code's external terminal with `"terminal.external.osxExec": "/Applications/rmux.app"`. Cmd+Shift+C opens or reuses the folder's named workspace and activates its window. No extension or socket setup required.
- Explicit automation activation now brings the application forward as well as selecting its window.
- Option+Left/Right moves by word with standard shell bindings; negotiated Kitty keyboard input remains intact. Cmd+Left/Right sends line-start/end controls, and Cmd+Backspace sends Ctrl+U.
- Open Settings File uses the configured external editor, falling back to TextEdit on macOS. Socket restart notices remain accurate across repeated settings reloads.

See the [VS Code setup guide](../guide/vscode.md).

## Terminal and interface polish

- Open compiler paths at a line and column in a configured editor, including quoted paths with spaces. Link feedback distinguishes missing directory context, remote files, and unsupported targets.
- Tab overflow keeps pane controls visible. Detailed tab tooltips are formatted on hover rather than on every redraw.
- Shared sidebar group controls have consistent titles, member counts, and add buttons. The WASM demo gains a searchable terminal-tab chooser.
- A duplicate tooltip registration caught during native review is fixed before publication.

## Scope

macOS Apple Silicon DMG and ZIP, Linux x86-64 tarball, and Windows x86-64 ZIP are
built on GitHub. macOS is signed and notarized, with Sparkle updates. Linux and
Windows remain platform previews; native Windows validation is deferred.
Cross-Space switching and VS Code switching latency have not been measured.
Projects with identical folder names share the workspace name. Remote file
opening and hosted shell sessions in the WASM demo remain unsupported.
