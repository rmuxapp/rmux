# rmux 0.1.13 — preview

This release improves project commands, Settings, and keyboard focus.

## Project and editor workflows

- Configured commands accept `{project_dir}` as a complete argument. Your VS Code return shortcut can target the original project even after changing terminal directories or renaming the workspace.
- Local commands that open a dedicated build or test workspace retain that project identity. Both command pickers preview the resolved target and explain missing project context.
- Settings includes a VS Code editor configuration example and an option to open the settings file without the configured editor, useful when repairing its path.

## Interface and navigation

- Sidebar directory labels show the folder name, with the full path in the tooltip.
- Settings has a compact footer with two aligned rows of actions.
- Opening the command palette from an inspector restores terminal context. Shortcuts, configured commands and layout pickers use that same context.
- Palette search keeps command abbreviations while avoiding unrelated matches from scattered letters in long paths.
- Pull-request lookup prefers open PRs and reports ambiguous matches instead of choosing an arbitrary result.

## Performance

- Bash and zsh reuse encoded working-directory text between prompts when the directory has not changed. Prompt and directory reporting still runs on every prompt.

## Downloads and validation

GitHub builds the signed and notarized macOS Apple Silicon DMG and ZIP, Linux
x86-64 tarball, and Windows x86-64 ZIP. macOS updates use Sparkle.

Focused matcher, configured-command, Settings, PR lookup and shell-integration
checks passed during development. Native review covered the compact Settings
layout and Settings → command palette → next terminal focus. Broader native
interaction, multi-window VS Code focus, and Windows runtime validation remain
pending. Automatic Bash login integration remains unsupported.
